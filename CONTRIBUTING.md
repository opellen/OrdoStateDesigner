# Contributing

Issues are welcome — bugs, questions, ideas, disagreements. A machine file that
reproduces a problem is the most useful thing you can send.

Pull requests are not accepted. State Designer is maintained by one person in
the time left over from a day job, and reviewing external code costs more than
writing it. Report the bug, describe the change you have in mind, or attach a
patch to the issue; it is read like any other report, and the change lands from
the maintainer's tree. SQLite works the same way.

## Reporting a bug

Include:

1. The version from the window title.
2. Your OS and Qt kit (for example Qt 6.11 MinGW on Windows 11).
3. The `.sdm` file, or the smallest machine that shows the problem, and the
   steps you took.
4. What you expected and what happened instead.
5. For a crash, the `sd.crash:` block from `state-designer.log` in the system
   temp directory (`%TEMP%` on Windows). It holds the walked stack and a
   ready-made `addr2line` command; the exe snapshot that command names is
   written next to the log.

For a build problem, run `state-designer --smoke` from the repo root first and
paste its last lines. It stops at the first failing phase and names it.

## Ideas and questions

Open an issue. Say what you were trying to do, not only what you want added.
The app has one authoring model — XState v5 vocabulary, one machine per
document, the same JSON driving the simulator and the generated C++ — and a
request that fits it is easier to take than one that needs a second model.

## Development

The build needs Qt 6 (Core, Widgets, Network, Svg) and a checkout of the
[ordo framework](https://github.com/opellen/Ordo) next to this repository, or
its path in `-DORDO_DIR`. See the README's *Building* section for the lookup
order and the build options.

```bash
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=<Qt6 prefix>
cmake --build build
./build/state-designer --smoke
```

`--smoke` is the headless suite: model, undo journal, simulator, code
generation, import/export and the twin check that the interpreter and the
generated C++ produce the same trace. The app's own canvas machine is
generated by the same pipeline, so after touching the generator also run

```bash
./build/state-designer --machine-drift-check src/machines/note-editor.sdm src/view/generated
```

Run the executable from the repo root; `--smoke` resolves machine files
relative to the working directory.
